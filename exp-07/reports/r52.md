# r52 overflow-free exact closure

## 1. Setup

Fix a positive repeated cube difference `D` and three positive representations

```text
A^3-a^3 = B^3-b^3 = C^3-c^3 = D,
a<b<c.
```

Put

```text
K01 = b^3-a^3,
K02 = c^3-a^3.
```

A third layer over the same base triple would have positive roots `(p,q,r)` and a common shift `E` with

```text
p^3-a^3 = q^3-b^3 = r^3-c^3 = E.
```

## 2. Common-lower-endpoint closure lemma

Such a layer exists if and only if there is a positive integer `p` and positive integers `q,r` such that

```text
q^3-p^3 = K01,
r^3-p^3 = K02.
```

Proof. If a layer exists, subtract its first equality from the second and third. Conversely, if the two displayed difference representations have the same lower endpoint `p`, define `E=p^3-a^3`. Then

```text
q^3-b^3
 = (q^3-p^3)+(p^3-a^3)-(b^3-a^3)
 = E,
```

and identically `r^3-c^3=E`.

Therefore closure is exactly the intersection of the sets of lower endpoints of positive representations of `K01` and `K02`.

For the normalized positive ordering `0<D<E`, the only relevant common endpoint satisfies `p>A`; `p=a` is the base layer and `p=A` is the already known `+D` layer. A final solution check still requires the nine roots to be pairwise distinct.

## 3. Why this removes the 128-bit caveat

The closure test never forms `p^3`, `q^3`, `r^3`, or `E`. It only reconstructs representations of the two fixed transverse differences and compares their lower endpoints. Hence a very large second offset cannot overflow a fixed-width cube calculation.

For `D <= 2^64-1`, every lower endpoint `x` of a positive representation `y^3-x^3=D` obeys

```text
D >= (x+1)^3-x^3 = 3x^2+3x+1 > 3x^2,
```

so `x < 2^32/sqrt(3) < 2^32`. Consequently, for two such endpoints `a,b`,

```text
(b^3-a^3)/(b-a) = a^2+ab+b^2 < 2^64.
```

Thus the existing factorization-based reconstruction of representations of `K01,K02` may keep the known-endpoint quotient in 64 bits while the differences themselves remain in 128 bits. Candidate lower endpoints of transverse representations may exceed 32 bits; they need only 64-bit storage, and no absolute cube of such an endpoint is required by the new closure test.

## 4. Run 32273871282 tail certificate

The full r25 tail produced 20 triples surviving the bidirectional `all3` filter. For each of those 20 triples, exact reconstruction of `Rep(K01)` and `Rep(K02)` shows that their common lower endpoints are exactly

```text
{a, A}.
```

Thus the only common layers are the base layer and the already known `+D` layer; there is no third positive layer at all. This rejects all 20 final tail candidates without computing a second shift.

This is stronger than the old closure path for this run: all 20, including the three for which the old code never entered its `exact` counter, are rejected by one uniform overflow-free criterion.

## 5. Scope

This repairs the *closure method*. It does not retroactively re-run the older finite `d1/d2` frontiers, whose stored summaries do not contain every candidate triple needed to apply the new intersection test after the fact. Re-certifying those old intervals requires either a new scan with this closure or sufficiently detailed preserved candidate data.
