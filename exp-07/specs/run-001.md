# Run 001 — GitHub Actions long search

## Execution

- Provider: GitHub Actions.
- 20 matrix jobs, maximum parallelism 20.
- Observed hosted runner capacity: `nproc=1`.
- One native search process per job.
- Six target classes distributed as 4,4,3,3,3,3 jobs.
- Parameter ceiling supplied to every worker: 2350.
- Search time per worker: 19,800 seconds.
- Job timeout: 360 minutes.
- Smoke required before matrix launch.

## Partition

Class/job mapping:

- class 0: jobs 0..3, shards 0..3 of 4;
- class 1: jobs 4..7, shards 0..3 of 4;
- class 2: jobs 8..10, shards 0..2 of 3;
- class 3: jobs 11..13, shards 0..2 of 3;
- class 4: jobs 14..16, shards 0..2 of 3;
- class 5: jobs 17..19, shards 0..2 of 3.

Each worker processes its assigned first-parameter indices in increasing block-cyclic order and uses the full in-memory lookup generated from the parameter ceiling for the second/third relation.

## Acceptance

- Exact integer arithmetic decides the multiplicative lookup.
- Floating point is used as a near-cancellation prefilter.
- Persisted records are replayed with exact Python rational arithmetic.
- Any accepted solution must reconstruct nine positive pairwise-distinct integers and pass all six cube-sum equalities exactly.

## Artifact protection

Each job packs diagnostics and search records into a tarball, encrypts it with a random AES-256 key, encrypts that key with `exp-07/k0.pub`, deletes plaintext detail files, and uploads only encrypted detail plus hashes and a small package manifest.

The matching private key is intentionally NOT stored in this public repository.

## Result

See `../reports/compute-summary-2026-08-17.md`.

The 2350 ceiling was not fully exhausted: every worker reached the 19,800-second internal time limit. Coverage must be reported from the explicit shard summaries, not from the requested ceiling alone.
