# Run 000

## Execution

- 30 jobs.
- 4 independent workers per job.
- 900 seconds of compute per job.
- 25-minute job timeout.
- Manual launch only after smoke validation.

## Work partition

- Four target classes.
- Job allocation: 8, 8, 7, 7.
- Four workers per job.
- Deterministic block-cyclic partitioning.
- Checkpoint after each completed block.

## Requirements

- Generate target data exactly from committed source.
- Use exact arithmetic for acceptance decisions.
- Use inexpensive filters before expensive exact work.
- Reconstruct every surviving record from the original constraints.
- Verify accepted records independently.

## Smoke

One runner, four workers, no more than 3 minutes of compute. Validate generation, filtering, exact solver path, checkpoint/resume, collection, memory use, and throughput.

## Budget rationale

Thirty 15-minute compute jobs use 7.5 machine-hours for the main matrix. The remaining monthly budget is intentionally reserved for setup/collection overhead, smoke validation, and a targeted rescue if a shard fails. Do not increase the runtime without an explicit new authorization.

## Artifacts

Record source SHA, target ID, worker ID, completed block IDs, counters, accepted records, machine diagnostics, dependency versions, and failure state.

The collector must distinguish completed coverage from missing or failed coverage.
