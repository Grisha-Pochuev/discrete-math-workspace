# «Мона Лиза» (100 000 точек): правила измерения и проверки результата

**Проверено по опубликованным правилам: 2 ноября 2026 года.**  
Этот документ фиксирует **официальную целевую величину** и отделяет её от вспомогательных показателей. Он не заменяет подтверждение результата организатором.

## 1. Исходная задача и условие премии

- Официальная задача: [Mona Lisa TSP Challenge](https://www.math.uwaterloo.ca/tsp/data/ml/monalisa.html).
- Единственный исходный набор координат для сравнения: [mona-lisa100K.tsp](https://www.math.uwaterloo.ca/tsp/data/ml/mona-lisa100K.tsp), 100 000 точек.
- Публично указанная длина лучшего маршрута: **5 757 191**.
- На официальной странице предложено **$1000 первому человеку, нашедшему маршрут строго короче 5 757 191**.
- Следовательно, необходимая длина по официальным правилам: **не более 5 757 190**. Равенство 5 757 191 не подходит.
- Публикуемая нижняя граница **5 757 084** — не пример построенного маршрута и не доказательство того, что возможно уменьшить длину хотя бы на единицу.

Источники: [официальная страница и формулировка премии](https://www.math.uwaterloo.ca/tsp/data/ml/monalisa.html), [опубликованный исходный маршрут 5 757 191](https://www.math.uwaterloo.ca/tsp/data/ml/tour/monalisa_5757191.tour).

## 2. Как именно считается длина

Для этой задачи задан тип расстояния **`EDGE_WEIGHT_TYPE: EUC_2D`** согласно формату TSPLIB. Для точек `i` и `j` с координатами `(x_i, y_i)` и `(x_j, y_j)` вес **одного ребра** равен:

```text
d(i,j) = nint(sqrt((x_i-x_j)^2 + (y_i-y_j)^2))
nint(t) = floor(t + 0.5)   для t >= 0
```

Критически важно: **сначала округляется длина каждого отдельного ребра, затем складываются целые веса**. Округлить только итоговую сумму — неправильно. `round()` в Python для граничных случаев может применять другое правило округления, поэтому его не следует использовать как определение `nint`.

Маршрут — **замкнутый цикл** через все 100 000 разных точек. Если порядок посещения `p[0], ..., p[n-1]`, то

```text
L = sum(d(p[k], p[(k+1) % n]) for k in range(n))
n = 100000
```

Последнее ребро **возвращает из последней точки в первую**. Оно тоже учитывается. Официальная длина `L` всегда **целое число в условных координатных единицах**, не сантиметры и не пиксели изображения на экране.

Пример: между `(0,0)` и `(1,1)` геометрическая длина `sqrt(2) ≈ 1.4142`, а официальный вес ребра равен `1`.

Первоисточник правил: [Герхард Райнельт, спецификация TSPLIB95, §2.1 «Euclidean distance»](https://comopt.ifi.uni-heidelberg.de/software/TSPLIB95/tsp95.pdf); [сайт TSPLIB95](https://comopt.ifi.uni-heidelberg.de/software/TSPLIB95/).

## 3. Что делать с дробными улучшениями

Можно для исследования отдельно считать длину **без округления рёбер**:

```text
L_exact = sum(sqrt((x_a-x_b)^2 + (y_a-y_b)^2) for each cycle edge (a,b))
```

Она полезна как дополнительный показатель, но **не является официальным критерием премии**. Уменьшение `L_exact` на `0.1` при неизменной `L = 5757191` **не удовлетворяет публичному условию**. В обратную сторону тоже нельзя делать вывод только из `L_exact`: любой кандидат для премии нужно проверять именно через `L`.

## 4. Какой результат проверять и сохранять

Чтобы утверждать, что найден маршрут, удовлетворяющий условию, необходимо проверить:

1. Использован именно неизменённый исходный файл `mona-lisa100K.tsp`.
2. В кандидатном маршруте **ровно 100 000 точек**, каждая с уникальным номером от 1 до 100 000; нет пропусков и повторов.
3. Маршрут замкнут; ребро «последняя → первая» включено.
4. Все веса вычислены как `EUC_2D` с **округлением каждого ребра**.
5. Независимый пересчёт официального исходного маршрута выдаёт **5 757 191**; пересчёт кандидата выдаёт **не более 5 757 190**.
6. Сохранён полный порядок точек, точное целочисленное значение длины и контрольная сумма файла с маршрутом.

Для обмена результатом подходит формат TSPLIB `TOUR` (`TYPE: TOUR`, `DIMENSION: 100000`, `TOUR_SECTION`, далее 100 000 идентификаторов вершин, затем `-1` и `EOF`). Пример оформления см. в [исходном официальном маршруте](https://www.math.uwaterloo.ca/tsp/data/ml/tour/monalisa_5757191.tour) и [описании формата TSPLIB95](https://comopt.ifi.uni-heidelberg.de/software/TSPLIB95/tsp95.pdf).

В этой папке уже есть независимый проверяющий скрипт [`verify_lkh_tour.py`](verify_lkh_tour.py), который считает веса без ошибок вещественного округления, проверяет уникальность точек и сравнивает кандидата с образцом. Пример вызова из корня репозитория:

```bash
python monalisa-tsp-search/verify_lkh_tour.py \
  --instance /path/to/mona-lisa100K.tsp \
  --candidate /path/to/candidate.tour \
  --reference /path/to/monalisa_5757191.tour \
  --report /path/to/verification.json
```

Проверяйте в отчёте поля `verified_reference_length`, `verified_candidate_length` и `strict_record_improvement`. Эти проверки нужны **до предъявления** результата; автоматическое получение приза они не подтверждают.

## 5. Процедура признания результата: что опубликовано и что нет

**Публично установлено:** награда $1000 обещана **первому** предъявившему более короткий маршрут. На странице есть исходные данные и опубликованный маршрут. Автор также пишет о готовности сообщать результаты вычислений.

**Не указано на странице как подробный регламент:** обязательная форма заявки, конкретный адрес для подачи, срок проверки, способ выплаты и обязательный формат подтверждающих файлов. Поэтому нельзя утверждать, что загрузка файла на GitHub сама по себе означает принятие результата или гарантированную выплату.

**Практически разумный порядок:** сохранить воспроизводимый полный маршрут и независимую проверку, затем **обратиться к организатору через контакты, подтверждённые на официальном сайте**, уточнить действительность премии и способ представления результата. Публично объявлять об официальном признании только после подтверждения от организатора.
